# Portcullis

A security engineering toolkit built to match the Mysten Labs Security Engineer posting: bug bounty operations, audit tracking, code review with variant analysis, software supply chain defenses, anti-scam detection for a Sui-style ecosystem, and security tooling with known-clean checks.

It is a portfolio project, not a product. It uses real public data where a sandbox can reach it, says plainly where it uses invented data, and records every bug it hit along the way as an incident with a failing test and a fix.

## Results

All numbers come from `python -m portcullis` (see `docs/REPORT.md`).

| Area | Result |
| --- | --- |
| npm registry signatures | 40 of 40 real signatures verify (ECDSA P-256); tampering with integrity or version breaks verification |
| Tarball integrity | 10 of 10 real tarballs match their published sha512 |
| Known-clean | 0 high or critical findings on 10 real tarballs; 0 of 5 real Sui Move files and 0 of 113 real npm JS files flagged as drainers |
| GitHub Actions | 13 real workflows scanned; real findings include unpinned third-party actions and missing permissions; 5 are clean |
| Compromised packages | debug@4.4.2, backslash@0.2.1 and color-name@2.0.1 recognised from real GHSA advisories; real debug@4.4.3 is not flagged |
| Bounty triage | 40 synthetic reports, 4 duplicates found, prompt-injection report decided as severity none, 8 recurring classes |
| Anti-scam | tuned corpus 1.0/1.0 (regression check only); holdout written afterwards: precision 1.0, recall 0.923 |
| Code review | 7 Semgrep rules from fixed bugs; 0 hits on fixed code, real Sui Move and real npm JS |
| Incidents | 19, each with a reproduce commit that fails and a fix commit that passes |

## How the posting maps to the code

| Posting responsibility | Where |
| --- | --- |
| Run bug bounty: triage, severity, payouts and budget, fix validation | `portcullis/bounty/triage.py`, `fixcheck.py` |
| Turn recurring report classes into automated checks | `triage.recurring` feeds `rules/portcullis.yml` |
| Own audit engagements and track to fix validation | `portcullis/audit/tracker.py` |
| Code and design review in Rust, TypeScript, Move; variant analysis | `target/`, `rules/`, INC-8 to INC-18 |
| Supply chain: CI/CD, packages, provenance and signing | `supplychain/actions.py`, `npm.py`, `lockfile.py`, `provenance.py`, `intel.py` |
| Anti-scam: phishing sites, malicious dApps, drainers | `portcullis/abuse/detect.py` |
| Security tooling with known-clean checks | every detector has real-data clean tests; `tests/test_rules.py` |

## Run it

```
make install
make test      # pytest, cargo test, node --test
make report    # writes out/report.json and docs/REPORT.md
make verify    # re-runs every incident's reproduce and fix commits
```

Needs Python 3.11+, Node 22.18+ (type stripping), and a Rust toolchain (std only, offline).

## Real and invented

Real: workflows from public repositories (two from MystenLabs/sui), Sui framework Move files, npm metadata, tarballs and registry keys, GHSA and RustSec advisories, the CISA KEV catalog. See `data/SOURCE.md`.

Invented: all bounty reports and the audit engagement, the anti-scam corpus and holdout, malicious package fixtures (inert, pattern only), the Treasury target code, and the typosquat popularity list.

## Limits

- Move was never compiled here; Move findings and fixes are pattern-checked only.
- No live bounty platform, Endor Labs, wallet or chain. No LLM is called; injection safety is shown by a deterministic decision that ignores a drafted severity.
- `semgrep --validate` needs a blocked download, so rules are validated by loading them in real scans.
- The anti-scam corpus was tuned against; only the holdout is a fair estimate, and it is small (26).
- The MAC test counts bytes examined as a stand-in for timing.
- Workflow counts are aggregate statistics over public files, not a verdict on those projects.
